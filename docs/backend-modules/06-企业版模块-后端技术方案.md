# 企业版模块后端技术方案

## 1. 模块目标

企业版模块用于承接中大客户咨询、企业开通申请和后续企业成员体系扩展，是商业化的重要入口。

## 2. 第一版范围

第一版必须支持：

- 企业版介绍页配置读取
- 企业开通申请
- 企业销售线索提交

第一版可有限支持：

- 企业基础资料
- 企业成员查询

第一版不做：

- 企业 API 文档中心 2.0
- 私有化部署工作台 2.0
- 多语言 SDK 管理

## 3. 后端职责

- 管理企业申请
- 管理企业资料和开通状态
- 承接销售线索
- 为后续企业权限与共享积分账户预留结构

## 4. 接口建议

- `GET /api/v1/public/enterprise-config`
- `POST /api/v1/enterprises/applications`
- `GET /api/v1/enterprises/current`
- `GET /api/v1/enterprises/members`

## 5. 数据依赖

- `enterprises`
- `enterprise_members`
- `enterprise_applications`
- `enterprise_leads`

## 6. 流程建议

### 6.1 企业申请

1. 用户提交企业名称、联系人、手机号、规模、需求说明。
2. 写入 `enterprise_applications`。
3. 触发运营通知。
4. 后台审核通过后再创建正式 `enterprises` 记录。

### 6.2 企业账户

第一版即使不做完整企业协作，也建议把企业表、成员表建好，避免后续返工。

## 7. 风险点

- 申请与正式企业混用
- 个人账号和企业账号权限边界不清

建议：

- 申请表与正式企业表分离
- 企业开通后再发生成员关系绑定

## 8. 模块结论

企业版第一版后端重心是“线索和申请承接”，不是完整企业工作台。数据结构要为后续企业权限、企业共享积分账户预留，但业务界面保持轻量。

# 首页模块后端技术方案

## 1. 模块目标

首页模块负责承载平台对外展示能力，为访客提供：

- 平台价值说明
- 核心能力入口
- 品牌背书和案例展示
- 套餐与企业咨询入口

该模块本身不承载复杂业务交易，但它是流量进入登录、生成、咨询、企业转化的起点。

## 2. 第一版范围

第一版首页后端必须支持：

- 首页静态配置聚合
- 成功案例列表
- 品牌/客户背书列表
- 首页 CTA 跳转配置
- 企业咨询线索提交入口

第一版不需要支持：

- 后台可视化 CMS
- A/B 实验系统
- 多语言发布系统

## 3. 前端现状分析

当前前端首页已经具备明确模块结构：

- Hero
- 核心能力展示
- 数据背书
- 品牌 Logo
- 成功案例
- 套餐入口
- 企业版入口

当前数据来自 `mockService.getHomeConfig()`，说明后端只需要提供一个聚合型只读接口即可先完成替换。

## 4. 后端职责

- 对外提供首页聚合配置接口
- 管理案例、品牌和首页文案的发布态
- 收集首页产生的咨询线索
- 记录基础埋点上下文所需的内容版本号

## 5. 接口方案

建议接口：

- `GET /api/v1/public/home-config`
- `GET /api/v1/public/cases`
- `POST /api/v1/leads`

响应特点：

- `home-config` 返回首页各区块配置
- `cases` 返回分页或固定数量案例
- `leads` 提交企业咨询或销售线索

## 6. 数据模型建议

第一版可以沿用较轻数据结构，不必一开始做完整 CMS。

建议新增或复用：

- `enterprise_leads`
- 可新增 `home_cases`
- 可新增 `brand_showcases`
- 可新增 `site_contents` 用于聚合静态区块

若希望减少建模成本，也可将首页配置先放在 JSON 配置表中，再逐步结构化。

## 7. 安全与校验

- `POST /leads` 需要限流
- 对手机号、企业名、联系人做格式校验
- 需要防刷与重复提交保护
- 可增加图形验证码或行为校验开关

## 8. 开发优先级

P0：

- 首页配置读取
- 案例读取
- 销售线索提交

P1：

- 首页配置缓存
- 线索重复检测

## 9. 模块结论

首页模块后端应保持轻量，重点不是复杂业务，而是稳定输出聚合内容和承接咨询转化。第一版以“聚合读取 + 线索提交”为核心即可。

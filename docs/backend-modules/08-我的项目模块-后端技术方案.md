# 我的项目模块后端技术方案

## 1. 模块目标

项目模块用于把任务和结果按业务主题沉淀，帮助用户管理批量生成内容，而不是让任务历史零散存在。

## 2. 第一版范围

第一版必须支持：

- 项目列表
- 项目详情
- 项目与任务关联
- 项目搜索和筛选
- 项目内批量下载入口

## 3. 前端现状分析

当前前端项目页已具备：

- 项目卡片
- 详情抽屉
- 批量下载入口

说明项目模块第一版至少要完成“列表 + 详情 + 任务聚合”三件事。

## 4. 后端职责

- 管理项目实体
- 维护项目和任务的关联关系
- 提供项目统计信息
- 支撑项目级下载

## 5. 接口建议

- `GET /api/v1/projects`
- `POST /api/v1/projects`
- `GET /api/v1/projects/{id}`
- `PATCH /api/v1/projects/{id}`
- `DELETE /api/v1/projects/{id}`
- `GET /api/v1/projects/{id}/tasks`
- `POST /api/v1/tasks/batch-download`

## 6. 数据依赖

- `projects`
- `project_items`
- `generation_tasks`
- `download_packages`

## 7. 实现要点

- 项目不是任务副本，而是任务聚合容器
- 项目统计字段如 `task_count`、`last_activity_at` 可以冗余缓存
- 删除项目只做软删除，不影响任务账务记录

## 8. 风险点

- 项目与任务归属错乱
- 批量下载任务过大

建议：

- 所有项目查询带 `owner_type/owner_id`
- 项目批量下载走异步 ZIP 打包

## 9. 模块结论

项目模块是任务资产沉淀层。第一版不需要复杂协作能力，但必须保证“能看、能搜、能聚合下载”。

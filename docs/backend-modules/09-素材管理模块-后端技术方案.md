# 素材管理模块后端技术方案

## 1. 模块目标

素材管理模块负责承接上传、归档、查找和复用，是所有生成任务的输入基础。

## 2. 第一版范围

第一版必须支持：

- 秒传检查
- 单文件上传
- 批量上传
- 上传完成确认
- 素材列表
- 文件夹管理
- 收藏、标签、分类
- 素材软删除

## 3. 前端现状分析

素材管理页已经具备：

- 上传入口
- 素材网格列表
- 标签展示
- 文件夹入口占位

因此后端至少要提供稳定的列表和上传闭环。

## 4. 后端职责

- 文件校验
- 对象存储上传编排
- 素材元数据提取
- 缩略图生成
- 素材归属与权限控制
- 素材分类、收藏、文件夹管理

## 5. 接口建议

- `POST /api/v1/uploads/check`
- `POST /api/v1/uploads/init`
- `POST /api/v1/uploads/complete`
- `POST /api/v1/uploads/batch-init`
- `GET /api/v1/assets`
- `GET /api/v1/assets/{id}`
- `PATCH /api/v1/assets/{id}`
- `DELETE /api/v1/assets/{id}`
- `GET /api/v1/folders`
- `POST /api/v1/folders`
- `PATCH /api/v1/folders/{id}`
- `DELETE /api/v1/folders/{id}`

## 6. 数据依赖

- `assets`
- `asset_folders`

## 7. 上传方案

建议使用两阶段上传：

1. 业务服务校验并签发上传参数。
2. 前端直传对象存储。
3. 上传完成后回调业务服务。
4. 业务服务异步提取元数据、审核并更新素材状态。

## 8. 风险点

- 文件类型伪造
- 孤儿文件残留
- 用户越权访问素材

解决建议：

- 服务端验证真实 MIME
- 定时清理未绑定对象
- 查询条件强制附带归属信息

## 9. 模块结论

素材管理模块不是“简单上传接口”，而是输入资产平台。第一版必须把上传、归属、列表和复用链路做扎实，否则任务模块会不稳定。

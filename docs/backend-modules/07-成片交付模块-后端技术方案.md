# 成片交付模块后端技术方案

## 1. 模块目标

成片交付模块承接“人工服务型交付”需求，属于平台的高客单服务入口，不直接走 AI 自动生成闭环。

## 2. 第一版范围

第一版必须支持：

- 成片交付服务说明读取
- 交付需求提交
- 附件上传关联
- 运营处理状态流转基础字段

## 3. 后端职责

- 接收交付需求
- 记录联系人、需求说明、交付时间、附件
- 关联用户和企业信息
- 对外提供需求状态查询基础接口

## 4. 接口建议

- `GET /api/v1/public/delivery-config`
- `POST /api/v1/delivery/requests`
- `GET /api/v1/delivery/requests`
- `GET /api/v1/delivery/requests/{id}`

## 5. 数据依赖

- `delivery_requests`
- `delivery_request_assets`
- `delivery_status_logs`

若首页、企业页也会提交咨询，则可与 `enterprise_leads` 协同，但不建议混成一张表。

## 6. 流程建议

1. 用户上传素材附件。
2. 提交交付需求。
3. 生成受理编号。
4. 运营处理状态流转：
   - 已提交
   - 评估中
   - 已确认
   - 制作中
   - 已交付
   - 已关闭

## 7. 风险点

- 用户上传资产和交付附件的归属关系不清
- 运营处理记录丢失

建议：

- 附件必须使用正式 `asset_id` 关联
- 状态变更写日志表，不直接覆盖

## 8. 模块结论

成片交付模块是“服务单系统”的轻量版本。第一版不需要复杂工单平台，但必须把需求、状态、附件和日志链条保存完整。

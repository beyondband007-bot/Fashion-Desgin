# 前端现状对齐只读接口模块技术方案
## 1. 模块目标

本模块的目标，不是继续扩任务中心，而是把当前前端页面已经存在、但仍依赖 `mockService` 的只读数据能力，快速对齐到真实后端接口。

当前重点补齐：

- 素材列表
- 项目列表
- 套餐列表
- 积分流水列表
- AI 工作台模型 / 场景 / 最近结果的前端兼容字段

## 2. 为什么这一阶段要单独做

当前前端页面已经具备较完整的页面结构，但后端能力存在明显断层：

- 工作台之外的多个页面仍完全依赖本地 mock
- 工作台接口虽已存在，但返回结构与当前前端使用的数据结构不完全一致
- 一个人同时开发前后端时，如果没有一层“前端现状对齐接口”，前端切真实接口成本会被放大

因此这一阶段优先做“前端可直接吃的数据出口”，而不是继续扩新的业务深度。

## 3. 设计范围

本模块纳入范围：

- `GET /api/v1/assets`
- `GET /api/v1/projects`
- `GET /api/v1/plans`
- `GET /api/v1/credits/transactions`
- 增强 `GET /api/v1/models`
- 增强 `GET /api/v1/scenes`
- 增强 `GET /api/v1/workbench/recent-results`
- 增加前端只读接口验收脚本

本模块暂不纳入范围：

- 登录注册
- 支付下单
- 素材上传
- 项目详情
- 积分冻结 / 结算真实闭环
- 前端改造

## 4. 核心设计原则

### 4.1 优先兼容，不推翻现有接口

已有工作台接口已经被现有验收脚本覆盖，因此不能粗暴改 DTO 结构。

本模块采取：

- 保留现有字段
- 增补前端兼容字段
- 保证旧验收脚本继续可跑

### 4.2 先做只读接口，降低联调阻力

当前最需要先动起来的是：

- 页面可打开
- 列表可展示
- 下拉可渲染
- 最近结果可回填

因此本模块优先提供只读能力，不把开发周期拖进上传、详情、写操作。

### 4.3 优先复用现有双库，不新增 schema

当前数据库已经存在：

- `assets`
- `projects`
- `credit_transactions`
- `credit_accounts`

本模块直接复用现有结构；数据库为空时，允许返回 fallback 数据，保证前端开发不中断。

## 5. 接口设计

### 5.1 素材列表接口

- `GET /api/v1/assets`

返回目标：

- 直接支撑素材管理页卡片列表

字段设计：

- 保留后端标准命名
- 同时补前端当前使用的 `cover` / `updatedAt` 别名字段

### 5.2 项目列表接口

- `GET /api/v1/projects`

返回目标：

- 直接支撑“我的项目”列表卡片

字段设计：

- `title`
- `summary`
- `status`
- `updated_at`
- `task_count`
- `cover_url`
- 同时补 `updatedAt` / `taskCount` / `cover`

### 5.3 套餐列表接口

- `GET /api/v1/plans`

当前策略：

- 先静态化返回
- 不进入真实支付链路

字段设计：

- 保留 `monthly_price / yearly_price`
- 同时补 `monthlyPrice / yearlyPrice`

### 5.4 积分流水接口

- `GET /api/v1/credits/transactions`

数据来源：

- 优先读 `fashion_ledger.credit_transactions`
- 没数据时返回 fallback

字段设计：

- `created_at`
- 同时补 `createdAt`

### 5.5 工作台接口增强

增强以下接口：

- `GET /api/v1/models`
- `GET /api/v1/scenes`
- `GET /api/v1/workbench/recent-results`

增强方式：

- 保留原有字段供现有任务接口与验收脚本使用
- 新增前端当前页面直接可用字段

示例：

- `models` 增补 `avatar / race / age / style / bodyType / skinTone / hairColor / favorite`
- `scenes` 增补 `image / type / tone / lighting / style / usageCount`
- `recent-results` 增补 `id / image / sourceImage / type / createdAt`

## 6. 验收标准

满足以下条件，才算本模块通过：

- `GET /api/v1/assets` 可返回数组
- `GET /api/v1/projects` 可返回数组
- `GET /api/v1/plans` 可返回至少 1 个套餐
- `GET /api/v1/credits/transactions` 可返回数组
- `GET /api/v1/models` 仍满足原工作台脚本校验
- `GET /api/v1/models` 同时返回前端兼容字段
- `GET /api/v1/scenes` 同时返回前端兼容字段
- `GET /api/v1/workbench/recent-results` 可返回前端兼容字段
- 新增只读接口验收脚本可重复跑通

## 7. 风险与限制

- 当前仍然基于 demo 用户视角，不是完整登录态
- 套餐接口当前是静态目录，不代表支付链路已完成
- 项目和素材当前是列表级能力，不代表详情页已可用
- 当前只是给前端切真实接口提供出口，不代表页面已经改造完成

## 8. 下一步建议

本模块完成后，最合理的下一步不是继续扩只读接口，而是：

- 前端工作台切真实接口
- 前端项目 / 素材 / 套餐 / 积分页逐步替换 mock

优先顺序仍应是：

1. AI 工作台
2. 最近结果 / 全局任务状态
3. 项目 / 素材 / 套餐 / 积分列表

## 9. 结论

本模块的价值，在于把“已经画好的前端页面”与“已经存在的后端双库能力”真正接起来，形成一层低成本、可快速联调的只读接口层，为后续前端切真实接口清障。

# 最小任务主链路模块技术方案

## 1. 模块目标

最小任务主链路模块是后端第一次真正开始承载业务动作的模块，负责把前面已经完成的：

- 后端基础框架
- 双库 schema 基线
- 统一 DTO 与枚举

串成一条可执行的最小任务链路。

## 2. 当前范围

本模块当前落地的范围是：

- 任务预估占位接口
- 创建任务接口
- 任务列表接口
- 任务详情接口
- 任务事件查询接口
- 内存态任务仓储
- 积分冻结占位客户端

当前不包含：

- 真实数据库落库
- 真实积分服务调用
- 真实 AI 供应商执行
- WebSocket 实时推送

## 3. 为什么现在做这个模块

这是启动阶段中第一个真正把“任务”变成可执行业务的模块。

如果这一步不先落：

- WebSocket 没有真实事件源
- 项目页没有真实任务对象
- 多模块实时规范无从承接

## 4. 当前接口

已落地的最小接口：

- `POST /api/v1/tasks/estimate`
- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `GET /api/v1/tasks/{id}/events`

## 5. 当前实现策略

为了先打通主链路而不被工具链和外部系统阻塞，当前采用：

- 内存态 store 存任务和事件
- mock 账务冻结客户端返回余额快照
- 任务创建后直接进入 `queued`

这不是最终实现，而是最小业务骨架实现。

## 6. 当前代码结构

新增任务模块：

- `store/task.store.ts`
- `services/task.service.ts`
- `services/ledger.client.ts`
- `controllers/task.controller.ts`

并挂载到：

- `apps/biz-api/src/modules/system/app.ts`

## 7. 关键链路

### 7.1 任务预估

- 接收 `TaskEstimateRequestDto`
- 生成预估积分
- 生成 `quote_id`
- 存入内存报价池

### 7.2 创建任务

- 读取报价
- 构造 `TaskDetailDto`
- 写入任务 store
- 生成 `task.created` 事件
- 调积分冻结占位客户端
- 返回任务摘要、余额快照、`ws_channel`

### 7.3 查询任务

- 支持任务列表
- 支持任务详情
- 支持事件列表

## 8. 当前限制

- 还没有真实数据库持久化
- 服务重启会丢失任务数据
- 还没有任务状态自动流转 worker
- 还没有多条件过滤能力

## 9. 下一步衔接

本模块完成后，下一步建议优先进入：

- 任务持久化与 repository 模块

或者如果继续沿“业务链路可见性”推进，也可以进入：

- WebSocket 实时同步接入模块

但更稳妥的顺序仍然是先做任务持久化。

## 10. 结论

最小任务主链路模块的意义，不是完成最终任务系统，而是第一次让后端具备了“可创建任务、可查任务、可记事件”的业务能力，为后续持久化、实时同步和积分链路替换打下直接基础。

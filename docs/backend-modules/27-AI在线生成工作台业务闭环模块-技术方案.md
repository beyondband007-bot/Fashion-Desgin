# AI 在线生成工作台业务闭环模块技术方案
## 1. 模块目标

本模块的目标，是把 AI 在线生成工作台从“已有任务底座”推进到“真正可用的业务闭环”。

当前重点补齐：

- 模型列表
- 场景列表
- 最近结果
- 任务取消
- 任务重试
- 结果下载

## 2. 设计范围

本模块纳入范围：

- `GET /api/v1/models`
- `GET /api/v1/scenes`
- `GET /api/v1/workbench/recent-results`
- `POST /api/v1/tasks/{id}/cancel`
- `POST /api/v1/tasks/{id}/retry`
- `POST /api/v1/tasks/{id}/download`

## 3. 核心设计

### 3.1 目录数据先静态化

模型和场景当前采用静态目录返回，先满足工作台接入和接口稳定性，后续再切到真实表。

### 3.2 最近结果基于已完成任务聚合

最近结果不单独建表，直接基于：

- `generation_tasks`
- `task_outputs`
- `assets`

进行聚合；如果暂时没有输出资产，则返回占位图地址。

### 3.3 取消与重试走任务中心

取消和重试不走独立业务表，直接复用任务中心：

- 取消：修改原任务为 `cancelled`
- 重试：复制失败任务为新任务，保留 `parent_task_id`

### 3.4 下载接口优先返回真实输出

如果任务已有真实输出资产，则返回资产 URL；否则在当前阶段返回占位下载地址，保证前端接口先可接。

## 4. 验收标准

- 可查询模型列表
- 可查询场景列表
- 可创建工作台任务
- 运行中任务可取消
- 失败任务可重试
- 完成任务可下载
- 最近结果可查询到完成任务

## 5. 下一步建议

本模块完成后，下一步更适合进入：

- 前端工作台接真实接口模块

重点把当前前端 `mockService` 替换为真实接口调用，并接入全局任务中心。

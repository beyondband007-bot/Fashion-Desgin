# 31-AI生成页任务接口闭环接入-技术方案

## 1. 目标

让 `AI 生成` 页面从“纯前端模拟生成”升级到“优先走真实后端任务接口，再通过 WebSocket 回流页面状态”的闭环实现。

本方案解决的问题：

- 页面点击生成后不能只做本地假进度
- 页面需要与后端任务中心统一
- WebSocket 事件需要真正驱动页面状态变化
- 后端暂不可用时仍需保留可演示能力

## 2. 设计原则

### 2.1 接口优先

生成动作优先走真实任务接口：

- 先估价
- 再创建任务
- 再推进状态

### 2.2 状态单源

任务状态以全局任务中心为单一来源，页面不各自维护独立任务副本。

### 2.3 页面只消费

页面只关心：

- 当前活跃任务是谁
- 当前任务状态是什么
- 应该如何展示预览、进度、错误、最近结果

页面不直接处理 WebSocket 协议细节。

### 2.4 本地兜底

如果后端链路当前不可达，页面自动回退到本地 mock，保证开发效率。

## 3. 前端链路

### 3.1 接口层

文件：[src/api/frontend.ts](/F:/服装/Fashion-Desgin/src/api/frontend.ts:1)

新增能力：

- `estimateGenerateTask`
- `createGenerateTask`
- `transitionTask`

作用：

- 对接任务估价接口
- 对接任务创建接口
- 对接任务状态推进接口

### 3.2 全局任务中心层

文件：

- [src/store/taskStore.ts](/F:/服装/Fashion-Desgin/src/store/taskStore.ts:1)
- [src/services/taskRealtimeClient.ts](/F:/服装/Fashion-Desgin/src/services/taskRealtimeClient.ts:1)
- [src/hooks/useTaskRealtime.ts](/F:/服装/Fashion-Desgin/src/hooks/useTaskRealtime.ts:1)

作用：

- 维护全局单主 WebSocket
- 接收快照和增量事件
- 统一保存任务数据
- 为页面提供模块级过滤能力

### 3.3 页面工作台层

文件：[src/pages/AiGenerate/hooks/useGenerateWorkbench.ts](/F:/服装/Fashion-Desgin/src/pages/AiGenerate/hooks/useGenerateWorkbench.ts:1)

作用：

- 负责页面本地上传态与预览态
- 负责生成入口调用
- 记录 `activeTaskId`
- 根据任务中心中的活跃任务回流页面状态

## 4. 运行流程

### 4.1 点击生成

页面点击“生成”后：

1. 校验页面输入
2. 进入 `pending`
3. 调用 `estimateGenerateTask`
4. 调用 `createGenerateTask`
5. 保存 `activeTaskId`

### 4.2 状态推进

当前开发阶段使用“前端驱动后端状态推进”：

1. 定时调用 `transitionTask`
2. 后端持久化任务状态
3. 后端广播 WebSocket 事件
4. 前端任务中心接收事件并更新 `taskMap`
5. 页面通过 `activeTaskId` 读取最新任务状态

### 4.3 页面回流

页面根据任务状态执行映射：

- `queued / billing_pending` -> `pending`
- `processing` -> `processing`
- `completed` -> `completed`
- `failed / cancelled` -> `failed`

同时同步：

- `progress`
- `stage`
- `error_message`
- 完成后的结果图

## 5. 最近结果策略

最近结果优先从全局任务中心中读取当前模块完成任务：

- 使用模块过滤器读取 `recentCompletedTaskIds`
- 转换为前端 `RecentResult`
- 页面优先显示实时结果
- 无实时结果时回退 HTTP `/recent-results`

## 6. 结果图策略

当前开发联调阶段，后端任务摘要中尚未返回真实输出图 URL，因此页面先使用基于任务 ID 的占位结果图：

- 结果图：`picsum.photos/seed/{task.id}`
- 来源图：当前页面上传图

该策略仅用于联调阶段，后续可替换为真实输出资产 URL。

## 7. 失败兜底策略

若任务接口调用失败：

- 页面不直接中断
- 自动切回本地 mock 生命周期
- 保证演示、联调、页面开发继续进行

这使得前端和后端可以并行推进，不互相阻塞。

## 8. 当前适用范围

本方案当前适用于：

- `AI 生成` 页面
- 开发联调环境
- WebSocket 已就绪但异步执行器尚未接入的阶段

## 9. 后续升级方向

建议后续按以下顺序演进：

1. 接入真实上传接口与真实资产 ID
2. 接入后端异步执行器，取消前端推进状态
3. 接入真实输出资产与下载地址
4. 接入失败重试、取消生成、批量生成
5. 将同一模式扩展到其他生成模块

## 10. 验收标准

完成后应满足：

- 页面点击生成时优先调用真实后端任务接口
- 任务创建后能通过 WebSocket 回流页面状态
- 页面预览区会随任务中心状态实时变化
- 后端不可用时页面仍能自动回退本地 mock
- 最近结果区优先显示实时完成任务

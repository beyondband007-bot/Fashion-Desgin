# 任务实时同步模块技术方案
## 1. 模块目标

本模块的目标，是在当前任务创建、状态推进、事件落库都已稳定的前提下，落地后端单主 WebSocket 实时同步能力。

## 2. 设计范围

本模块纳入范围：

- 短效实时 token 接口
- 单主 WebSocket 网关
- 用户级任务事件广播
- 心跳与连接上限
- WebSocket 验收脚本

## 3. 核心设计

### 3.1 单主通道

后端仅提供一条统一通道：

- `POST /api/v1/realtime/token`
- `GET /api/v1/ws?token=...`

### 3.2 Token 机制

当前阶段采用：

- 短效 token
- 单次 upgrade 消费
- 内存存储

### 3.3 广播维度

当前按用户维度广播：

- `user:{userId}:tasks`

事件仍然带完整任务归属字段，前端可再按：

- `module`
- `project_id`
- `batch_id`
- `task_type`

做二次分发。

### 3.4 推送时机

后端严格遵守顺序：

1. 更新数据库
2. 记录 `task_events`
3. 发布 WebSocket 事件

## 4. 验收标准

- `POST /api/v1/realtime/token` 可返回短效 token
- `GET /api/v1/ws?token=...` 可建立连接
- 创建任务时可收到 `task.created`
- 推进到 processing 时可收到 `task.updated`
- 推进到 completed 时可收到 `task.completed`
- 事件按版本顺序递增

## 5. 下一步建议

下一模块应进入前端全局任务中心接入，重点实现单连接共享、模块级订阅和 fallback 轮询协调。

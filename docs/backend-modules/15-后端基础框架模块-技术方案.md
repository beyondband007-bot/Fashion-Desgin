# 后端基础框架模块技术方案

## 1. 模块目标

后端基础框架模块是整个后端系统的启动模块，负责建立：

- 双服务工程骨架
- 基础目录约定
- 服务启动入口
- 最小健康检查能力
- 统一后续模块挂载点

该模块不承担具体业务，但它决定后续认证、任务、积分、实时、支付等模块是否能稳定落地。

## 2. 为什么先做这个模块

根据当前开发顺序，第一阶段应先建立：

1. 工程形态
2. 后端骨架
3. 数据库基线
4. 任务主链路

因此，第一个实际开发模块不应是登录、任务或 WebSocket，而应是“后端基础框架模块”。

## 3. 模块范围

本模块首版范围：

- 创建独立 `backend/` 工作区
- 建立 `biz-api` 与 `ledger-service` 双服务目录
- 提供每个服务的 `main.ts`
- 提供最小 `/health` 接口
- 提供共享 TypeScript 基础配置
- 提供后续模块的目录挂载位置

本模块当前不包含：

- NestJS 依赖安装
- 数据库连接
- Redis、队列、Prisma
- 业务模块实现

## 4. 结构设计

建议结构：

```text
backend/
  apps/
    biz-api/
      src/
        main.ts
        modules/system/
    ledger-service/
      src/
        main.ts
        modules/system/
  packages/
    shared-kernel/
  tsconfig.base.json
  package.json
```

## 5. 当前实现策略

由于仓库当前尚未安装后端依赖，首版先采用 Node 原生 HTTP 启动方式，目的不是长期替代 NestJS，而是先完成：

- 后端目录落地
- 服务边界落地
- 启动入口落地
- 健康检查协议落地

后续切换到 NestJS 时，可以保留：

- 双服务结构
- `modules/system` 模块位置
- 统一响应结构
- 请求上下文约定

## 6. 输出内容

本模块产出：

- `backend/` 独立工作区
- `biz-api` 服务骨架
- `ledger-service` 服务骨架
- 共享 TS 基础配置
- 健康检查响应结构

## 7. 下一步衔接

本模块完成后，下一开发目标应进入：

- 数据库与 Prisma 基线模块

然后再进入：

- 任务主链路模块
- 实时同步模块

## 8. 结论

后端基础框架模块是启动阶段必须先完成的技术底座。它不解决业务问题，但它解决“后端从哪里长出来”的问题，是后续所有模块的承载层。

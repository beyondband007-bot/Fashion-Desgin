# 最小任务状态推进模块开发归纳
## 1. 本次开发目标

本次开发目标，是在已有真实写库和接口验收通过的基础上，尽快补齐任务最小状态推进能力。

重点不是扩功能面，而是为后续 WebSocket 和全局任务中心建立可靠状态源。

## 2. 本次实际完成内容

### 2.1 补充状态推进 DTO

更新文件：

- `backend/packages/shared-types/src/tasks.ts`

新增：

- `TransitionTaskRequestDto`

同时为任务事件补充：

- `from_status`
- `to_status`

### 2.2 新增状态推进接口

更新文件：

- `backend/apps/biz-api/src/modules/system/app.ts`
- `backend/apps/biz-api/src/modules/tasks/controllers/task.controller.ts`

新增接口：

### 2.3 实现最小状态机

更新文件：

- `backend/apps/biz-api/src/modules/tasks/services/task.service.ts`

完成内容：

- 只允许 `queued -> processing / failed`
- 只允许 `processing -> completed / failed`
- 非法流转直接报错
- 每次流转自动递增 `version`
- 完成态自动写入 `completed_at`
- 完成态自动归一 `progress = 100`

### 2.4 事件流补齐前后状态

更新文件：

- `backend/apps/biz-api/src/modules/tasks/repositories/prisma-task.repository.ts`

完成内容：

- TaskEvent 落库时写入 `fromStatus`
- TaskEvent 落库时写入 `toStatus`

这为后续前端乱序保护和事件回放打下了基础。

### 2.5 增加生命周期验收脚本

新增文件：

- `backend/scripts/verify-task-lifecycle-api.cjs`

新增脚本：

- `api:verify:lifecycle`

脚本会完成：

- 创建报价
- 创建任务
- 推进到 `processing`
- 推进到 `completed`
- 回查详情
- 回查事件流
- 校验版本号、事件顺序、前后状态

## 3. 本次开发解决的核心问题

### 3.1 任务系统只有创建态，没有生命周期

此前任务接口虽然能写库，但任务长期停在 `queued`，导致后续实时同步没有实际业务价值。

这次已经补上最小生命周期。

### 3.2 事件流缺少状态前后文

此前事件只有事件类型和快照，没有显式 `from_status / to_status`，后续前端做状态分发和防乱序会很吃力。

这次已经补齐。

### 3.3 缺少状态推进的自动验收工具

此前只有创建链路验收，没有生命周期验收。

这次补上了专门的生命周期脚本，可以重复执行。

## 4. 当前状态判断

到这一步，任务中心已经具备：

- 创建任务
- 查询任务
- 查询任务事件
- 推进任务状态
- 校验任务事件顺序

这意味着下一步可以开始进入任务实时同步层，而不是继续停留在纯数据库接口阶段。

并以当前已完成的状态源为基础接入：

## 6. 本次开发结论

这次开发完成的是“最小任务状态推进模块”。它把任务系统从“静态记录”推进成了“有生命周期的任务实体”，为后续的实时同步和多模块任务中心提供了真正可用的数据基础。

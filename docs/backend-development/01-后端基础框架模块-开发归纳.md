# 后端基础框架模块开发归纳

## 1. 本次开发目标

本次开发的目标是正式在仓库中落下后端工程的第一块可维护结构：

- 建立独立 `backend/` 工作区
- 建立双服务目录
- 提供最小服务入口
- 补齐本模块技术方案文档

## 3. 当前状态判断

本次开发完成后，仓库已经不再是“只有前端代码”的状态，而是具备了明确的后端落点。

当前后端状态属于：

- 已完成基础目录和服务边界落地
- 尚未进入 NestJS 正式依赖接入
- 尚未进入数据库、Prisma、Redis、任务模块开发

## 4. 为什么采用当前实现方式

当前先没有直接接入 NestJS，原因是：

- 仓库当前尚无后端依赖
- 这一步的目标是“工程落位”，不是“业务实现”
- 先把服务边界和目录约定落到代码中，后续再替换底层启动方式，成本更低

换句话说，这次开发重点是“把后端长出来”，不是“把后端一次做完”。

## 5. 已知限制

当前实现的限制如下：

- 还不是正式 NestJS 项目
- 还没有安装任何后端依赖
- 还没有数据库连接
- 还没有真实业务模块
- `ledger-service` 当前复用了部分基础系统代码，后续应抽到共享层

## 6. 下一步建议

本模块完成后，下一步应开发：

- 数据库与 Prisma 基线模块

优先内容：

- 双数据库连接策略
- Prisma schema 初版
- 第一批核心表
- migration 流程

## 7. 本次开发结论

这次开发完成的是“后端基础框架模块”，它解决了后续所有开发的挂载基础。接下来可以在这个骨架上继续推进数据库模块，而不需要再回头讨论后端工程从哪里开始。

# 双数据库巡检与结构确认验收文档
## 1. 验收目标

本验收文档用于确认当前后端数据库不是“没有新增数据库”，而是严格按项目既定双数据库方案落地：

- `fashion_biz`
- `fashion_ledger`

本次开发迭代新增的重点是：

- 新表
- 新字段
- 新接口
- 新脚本

而不是继续新增第三个、第四个数据库。

## 2. 当前数据库结构结论

当前项目只维护两套数据库：

- Biz 业务库：`fashion_biz`
- Ledger 账务库：`fashion_ledger`

这是与前期双数据库设计保持一致的结果，不是漏建库。

## 3. 当前已确认的 Biz 表

`fashion_biz` 当前核心表包括：

- `users`
- `auth_sessions`
- `verification_codes`
- `assets`
- `projects`
- `task_quotes`
- `generation_tasks`
- `task_inputs`
- `task_outputs`
- `task_events`

## 4. 当前已确认的 Ledger 表

`fashion_ledger` 当前核心表包括：

- `credit_accounts`
- `billing_tasks`
- `credit_transactions`
- `idempotency_keys`

## 5. 巡检脚本

已新增脚本：

- `npm run db:inspect`

作用：

- 直接输出当前双库名称
- 输出每个库的表数量
- 输出每个库的表清单

这可以避免后续再通过手工进入 MySQL 判断“数据库有没有建出来”。

## 6. 验收标准

满足以下条件，视为通过：

- MySQL 中存在 `fashion_biz`
- MySQL 中存在 `fashion_ledger`
- `fashion_biz` 能看到业务核心表
- `fashion_ledger` 能看到账务核心表
- `npm run db:inspect` 能正常输出结构化巡检结果

## 7. 验收结论

当前数据库状态正常。本次后端新增并不是继续扩数据库数量，而是在既定双数据库结构下持续扩展业务表、任务链路和工作台能力。

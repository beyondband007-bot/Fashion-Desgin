# 数据库开发文档（当前实现版）
## 1. 文档目的

本文档用于说明当前项目数据库的真实落地状态，而不是产品规划状态。

目标有三点：

- 让新同事快速知道当前数据库到底落了哪些库、哪些表、哪些字段
- 让后续开发可以在现有数据库基础上继续加功能，而不是重新猜结构
- 让数据库扩展、联调、巡检有明确入口

本文档基于当前代码仓库中的实际实现整理，适合作为后端、前端联调、测试、后续功能扩展的统一参考。

## 2. 当前数据库总览

当前项目采用严格的双数据库方案，不是多模块多数据库方案。

当前只存在两套数据库：

- `fashion_biz`
- `fashion_ledger`

职责划分如下：

- `fashion_biz`
  - 用户、认证、素材、项目、任务、任务事件
- `fashion_ledger`
  - 积分账户、冻结、结算、账务流水、幂等

这意味着：

- 后续新增业务功能，优先在这两套库内扩展
- 不要因为新增一个业务页面就新建一个数据库
- 数据库边界按“业务域”而不是按“页面”划分

## 4. 数据库初始化与巡检命令

### 4.1 基础命令

在 `backend/` 目录下执行：

- `npm run prisma:generate`
  - 生成双库 Prisma Client
- `npm run prisma:push`
  - 把双库 schema 推送到数据库
- `npm run db:prepare`
  - 推表 + demo 数据 bootstrap
- `npm run db:check`
  - 检查双库连通性
- `npm run db:inspect`
  - 输出当前双库结构

### 4.2 当前推荐的本地初始化顺序

1. 配置 `backend/.env`
2. 执行 `npm run prisma:generate`
3. 执行 `npm run db:prepare`
4. 执行 `npm run db:inspect`
5. 执行 `npm run db:verify:tasks`

### 4.3 巡检脚本

当前已新增数据库巡检脚本：

- [backend/scripts/inspect-db-structure.cjs](/F:/服装/Fashion-Desgin/backend/scripts/inspect-db-structure.cjs:1)

作用：

- 输出 Biz / Ledger 数据库名
- 输出表数量
- 输出表清单
- 明确当前项目就是双数据库，不是漏建库

## 8. 当前数据库扩展规则

### 8.1 新增业务功能时的优先原则

新增功能时，先判断是否可以复用现有表：

- 任务相关功能
  - 先看 `generation_tasks`
- 任务过程与同步相关功能
  - 先看 `task_events`
- 上传和结果相关功能
  - 先看 `assets` / `task_inputs` / `task_outputs`
- 项目聚合相关功能
  - 先看 `projects`
- 账务相关功能
  - 先看 `credit_accounts` / `billing_tasks` / `credit_transactions`

不要做的事情：

- 为某个页面单独建一套平行任务表
- 为“最近结果”“工作台结果”单独再建一张重复任务结果表
- 为每个模块建立独立任务中心表

### 8.2 新增字段时的优先原则

如果字段属于任务公共维度，优先加在 `generation_tasks`：

- 模块归属
- 页面来源
- 批次归属
- 扩展状态
- 重试与回滚上下文

如果字段属于一次状态变化快照，优先进 `task_events.payload_json`。

如果字段属于输出资源本身，优先进 `assets`。

## 9. 当前数据库变更策略

当前项目仍以开发迭代速度优先，数据库结构主要通过：

- `prisma db push`

完成本地同步。

已经保留的脚本：

- `prisma:migrate:biz`
- `prisma:migrate:ledger`

但当前并没有完整维护正式 migration 历史目录。

这意味着：

- 开发阶段可以继续使用 `db push`
- 真正进入测试/预发/生产规范化阶段后，需要补正式 migration 管理

## 12. 给后续开发同事的建议

如果你要继续开发数据库相关功能，优先顺序建议如下：

1. 先确认功能归属 Biz 还是 Ledger
2. 先判断是否能复用现有表
3. 如果必须加字段，优先加到现有任务主表或事件表
4. 修改 Prisma schema 后，先本地执行：
   - `npm run prisma:generate`
   - `npm run prisma:push`
   - `npm run db:inspect`
5. 如果改动影响任务主链路，再执行：
   - `npm run db:verify:tasks`
   - `npm run api:verify:tasks`
   - `npm run api:verify:lifecycle`

## 13. 结论

- `fashion_biz`
- `fashion_ledger`

这两个既有数据库之上持续扩展，而不是重新发散数据库边界。
